# 01 · 需求与验收

## 用户、范围与目标

目标用户是想查制度的新员工与内部支持人员。用户用自然语言提问，可选附带近几轮问答历史；系统在**虚构合成**知识库内查找证据并回答，或明确标注不确定性/资料缺口。

功能范围：本地文档元数据搜索、指定 ID 原文读取、答复（引用原文与文档 ID）、冲突呈现、失败重试机会、工具和决策次数上限、可审查 Trace。不包括对真实公司文档的连接、权限系统、在线更新或 Web UI。

## 成功标准

| 场景 | 输入示例 | 可观察成功标准 |
| --- | --- | --- |
| 明确答案 | 办公电脑怎么领取 | 完成、引用 D03 的原文、状态 complete |
| 资料冲突 | 差旅报销最晚何时提交 | D01/D02 均被读取，说明矛盾并请求核实范围，不私自取 15 或 30 天 |
| 资料外 | 食堂今晚的菜单 | 标明没有可支持的文档，不编造 |
| 相似改写 | 刚入职的新人如何领笔记本 | 仍能定位设备申领条款 |
| 上下文追问 | 前文询问办公设备；接着问需要审批吗 | 用上下文关联原问题，定位 D03 |
| 工具失败 | 强制使第一次搜索/读取失败 | Trace 含错误，下一轮允许模型调整动作（如有限重试） |
| 边界 | max_steps=1 / max_tool_calls=1 | 明确 incomplete，禁止虚报完成 |

**流程与真实决策证据是两回事**：测试中的脚本 Mock 只用于逻辑检查；最终需要配置实时模型并保留实际选择动作与观察的日志。Trace 的每一步必须包含实际工具参数、完整工具返回、后续动作及一句可公开的依据，不能记录或要求模型暴露隐藏思维过程。

## 输出契约

输出 `status`、`answer`、`citations:[{document_id,quote}]`、`gaps`、`trace`，可附带真实 API 响应统计的 token 使用量。`read_document` 只允许读取之前由成功检索返回的 ID；`quote` 必须是已读取原文的子串，不能引用尚未读取的搜索摘要。`not_found` 至少要有一次成功检索。制度冲突如无范围或优先级证据，必须作为冲突暴露。

## 最终验收结论

2026-10-28 使用 DeepSeek 官方 `deepseek-flash` 非思考模式完成七组实时场景，7/7 通过；26/26 离线测试通过。真实 Trace 覆盖明确答案、冲突、资料外、相似改写、上下文追问、搜索失败和读取失败。自动检查确认成功搜索后的下一动作是读取文档，而失败搜索后的下一动作是由模型选择再次搜索。
